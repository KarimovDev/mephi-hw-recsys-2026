# Прототип книжного рекомендательного сервиса

Домашнее задание по курсу "Рекомендательные системы". На датасете
[goodbooks-10k](https://www.kaggle.com/datasets/zygmunt/goodbooks-10k) построены и сравнены четыре подхода:
популярные книги, контентная модель на TF-IDF, Item-based CF и SVD. Также сделан простой гибрид для холодного старта.

Ноутбуки в виде HTML-страниц: https://karimovdev.github.io/mephi-hw-recsys-2026/

## Как запустить

Нужен [uv](https://docs.astral.sh/uv/).

```bash
uv sync                           # установка зависимостей
uv run python download_data.py    # скачать датасет в data/
uv run jupyter lab                # открыть ноутбуки
```

Ноутбуки нужно выполнять по порядку. Ноутбуки 2-4 сохраняют рекомендации моделей в папку `artifacts/`,
а 5 и 6 их читают. Прогнать всё из командной строки и пересобрать HTML можно так:

```bash
uv run jupyter nbconvert --to notebook --execute --inplace notebooks/*.ipynb
uv run jupyter nbconvert --to html --output-dir docs notebooks/*.ipynb
```

Полный прогон занимает пару минут.

## Логика решения

### Данные

В `ratings.csv` 980 тысяч оценок, 53 тысячи пользователей и 10 тысяч книг, заполнено 0.18% матрицы.
Две трети оценок приходятся на 4 и 5, у трети пользователей меньше пяти оценок. В этой версии датасета
у каждой книги не больше 100 оценок, поэтому перекос популярности виден только по столбцу `ratings_count`
из `books.csv` (данные Goodreads), а по самим оценкам его не видно.

### Разбиение

Временных меток нет, поэтому разбиение случайное: 20% оценок каждого пользователя уходят в тест.
Разбиение зафиксировано в `utils.split_ratings` и одинаково во всех ноутбуках.

### Модели

- Popularity: топ по средней оценке среди книг с не менее чем 50 оценками.
- Content-based: TF-IDF по названию и тегам книги, близость по косинусу. Для рекомендаций пользователю
  его профиль собирается как сумма векторов оценённых книг с весами-оценками.
- Item-based CF: косинусная близость между столбцами разреженной матрицы оценок. Оценка предсказывается
  как средневзвешенная по 20 наиболее похожим книгам из истории пользователя. Для top-N книги ранжируются
  по сумме произведений сходства на оценку.
- SVD: `surprise.SVD`, параметры подобраны по сетке с кросс-валидацией на train.
- Гибрид: Item-based CF для книг с оценками, контентная модель для книг без оценок, популярное для
  пользователей без истории.

### Оценка

Релевантной считается книга из теста с оценкой 4 или 5. Каждая модель выбирает top-10 из всех книг,
которые пользователь не оценивал в train. Метрики усредняются по 38 тысячам пользователей, у которых в тесте
есть хотя бы одна релевантная книга.

## Результаты

| Модель | Precision@10 | Recall@10 | nDCG@10 | RMSE на тесте |
|---|---|---|---|---|
| Random | 0.0003 | 0.0008 | 0.0006 | - |
| Popularity | 0.0005 | 0.0018 | 0.0012 | - |
| Content-based (TF-IDF) | 0.0473 | 0.1688 | 0.1315 | - |
| Item-based CF | **0.0820** | **0.2728** | **0.2272** | 0.852 |
| SVD | 0.0005 | 0.0015 | 0.0010 | **0.829** |

Для сравнения, RMSE предсказания глобальным средним равен 0.982.

Основные выводы (подробнее в ноутбуках 5 и 6):

- Для top-N рекомендаций лучше всех работает Item-based CF. В книжных данных связанные книги (серии, один автор)
  оценивают одни и те же люди, и модель это использует.
- SVD точнее всех предсказывает оценку, но при ранжировании по всему каталогу даёт результат на уровне случайной
  выдачи. Наверх попадают одни и те же книги с высоким средним рейтингом. Низкий RMSE ещё не означает хороших рекомендаций.
- Popularity здесь тоже не лучше случайной выдачи, но это следствие выборки, в которой у всех книг почти одинаковое число оценок.
- Контентная модель слабее коллаборативной, зато работает для книг без оценок. В эксперименте с 500 новыми
  книгами Item-based CF не нашёл ни одной из 6 623 релевантных оценок по ним, а гибрид нашёл 258
  без потери общей точности.
