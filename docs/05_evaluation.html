5. Оценка и сравнение моделей¶

Сравниваем top-N рекомендации всех моделей на отложенной тестовой выборке по метрикам Precision@K, Recall@K и nDCG@K.

Как устроена оценка:

  • В тесте 20% оценок каждого пользователя, в обучении моделей они не участвовали (utils.split_ratings).
  • Релевантной считаем книгу из теста, которой пользователь поставил 4 или 5. Тройка уже ниже средней оценки по датасету (3.86), считать её удачной рекомендацией нельзя.
  • Каждая модель выбирает top-10 из всех книг, которые пользователь не оценивал в train. Рекомендации посчитаны в ноутбуках 2-4 и сохранены в artifacts/.
  • Метрики считаем для пользователей, у которых в тесте есть хотя бы одна релевантная книга, и усредняем по пользователям.

Про неоценённые книги из выдачи мы ничего не знаем и считаем их нерелевантными. Поэтому абсолютные значения метрик получаются заниженными, но модели между собой сравнивать можно.

Метрики¶

Все три метрики считаются по матрице попаданий hits размера (пользователи x K): hits[u, i] = True, если книга на позиции i в выдаче пользователя u релевантна.

  • Precision@K: доля релевантных среди K рекомендованных.
  • Recall@K: доля найденных релевантных книг пользователя.
  • nDCG@K учитывает порядок. Попадание на позиции $i$ даёт вклад $1 / \log_2(i + 1)$, так что релевантная книга в начале списка ценится выше. DCG делится на IDCG, то есть на значение для идеальной выдачи, где все релевантные книги пользователя (но не больше K) стоят в начале.
In [3]:
def get_hits(user_ids, recs, relevant_matrix) -> np.ndarray:
    """hits[u, i] = True, если i-я рекомендация пользователя u есть среди его релевантных книг."""
    return relevant_matrix[user_ids[:, None] - 1, recs - 1].toarray().astype(bool)


def precision_at_k(hits, k):
    return hits[:, :k].sum(axis=1) / k


def recall_at_k(hits, n_relevant, k):
    return hits[:, :k].sum(axis=1) / n_relevant


def ndcg_at_k(hits, n_relevant, k):
    discounts = 1 / np.log2(np.arange(2, k + 2))  # позиции 1..k
    dcg = (hits[:, :k] * discounts).sum(axis=1)
    ideal_hits = np.minimum(n_relevant, k)        # сколько релевантных поместится в идеальный top-k
    idcg = np.cumsum(discounts)[ideal_hits - 1]
    return dcg / idcg

Проверка на примере¶

Пользователю рекомендованы 5 книг, релевантных у него три, в выдачу попали две, на 1-й и 3-й позициях. Вручную: Precision@5 = 2/5, Recall@5 = 2/3, DCG = $1 + 1/\log_2 4 = 1.5$, IDCG = $1 + 1/\log_2 3 + 1/\log_2 4 \approx 2.131$, nDCG $\approx 0.704$.

Во второй строке те же два попадания стоят на 4-й и 5-й позициях. Precision и Recall не меняются, а nDCG должен упасть.

def evaluate(recs, ks=(5, 10)) -> dict:
    hits = get_hits(eval_users, recs, relevant_matrix)
    result = {}
    for k in ks:
        result[(f"K = {k}", "Precision")] = precision_at_k(hits, k).mean()
        result[(f"K = {k}", "Recall")] = recall_at_k(hits, n_relevant, k).mean()
        result[(f"K = {k}", "nDCG")] = ndcg_at_k(hits, n_relevant, k).mean()
    result[("", "Покрытие каталога")] = len(np.unique(recs)) / N_BOOKS
    return result


metrics = pd.DataFrame({name: evaluate(recs) for name, recs in model_recs.items()}).T
metrics.columns = pd.MultiIndex.from_tuples(metrics.columns)
metrics.round(4)

Выводы по сравнению¶

Лучше всех с большим отрывом работает Item-based CF. В среднем из 10 рекомендаций 0.8 оказываются книгами, которые пользователь действительно высоко оценил в тесте, и модель находит около 27% таких книг. Это много, если учесть, что выбирать приходится из 10 тысяч книг, а у половины пользователей в тесте одна-две релевантные книги. Модель работает, потому что в данных много связанных книг (серии, один автор, один жанр). Тот, кто оценил одну книгу серии, с большой вероятностью оценил и другую.

На втором месте контентная модель. Она ловит ту же структуру (серии и жанры) через теги и названия, но не знает, какие из похожих книг на самом деле читают вместе. При этом оценки других пользователей ей не нужны совсем.

Сильно влияет способ ранжирования. Тот же Item-based CF с ранжированием по средневзвешенной предсказанной оценке теряет почти всё качество, потому что наверх попадают книги с одним слабым соседом, получившим пятёрку.

Popularity и SVD оказались на уровне случайных рекомендаций. Причины у них разные.

  • Popularity. В этой версии датасета у каждой книги примерно одинаковое число оценок, то есть вероятность встретить любую книгу в тесте одна и та же. Популярность здесь не несёт информации, а средняя оценка книги не говорит о том, станет ли пользователь её читать. На полных данных Goodreads с настоящим перекосом популярности этот бейзлайн был бы намного сильнее.
  • SVD. Модель обучалась предсказывать оценку для пары, которая уже есть в данных, и с этим справляется лучше всех (RMSE 0.83). Но она не отвечает на вопрос, какие книги пользователь выберет. В top-N попадают книги с самым высоким смещением $b_i$, почти одинаковые для всех, покрытие каталога около 1%. Получается, что низкий RMSE не гарантирует хорошего ранжирования.

Что касается длины истории, по Precision и Recall пользователей с разной историей сравнивать напрямую нельзя (у активных больше релевантных книг в тесте). Но по nDCG видно, что Item-based CF полезен даже при 1-3 оценках в истории, и с ростом истории качество растёт. Для пользователя совсем без истории ни одна из персональных моделей не работает.

У такой оценки есть ограничения. Разбиение случайное, а не по времени (меток времени нет), так что в train могли попасть оценки, поставленные позже тестовых. Офлайн-метрики считают неудачей любую книгу без оценки в тесте, хотя она могла бы понравиться. Надёжнее было бы проверить модели в A/B-тесте.
